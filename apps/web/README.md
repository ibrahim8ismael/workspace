# Browser client

Run `pnpm dev:web` at the repository root, then open http://localhost:5173. Use `pnpm dev` to start the web client and existing NestJS starter together. No Docker service starts automatically.

The entrypoint is `main.tsx`. It loads the authenticated account/company experience under `src/features/{auth,workspaces}`. Account entry, company directory, security and the full-screen office reuse the supplied OpenOfficeForAll dashboard and office-shell visual structures while calling this repository's APIs. The office shell mounts the renderer selected by the immutable server map version (Vivo for current offices) and `OfficeClient`; the legacy services remain unreachable, while Commons renderer support stays available only for any office still bound to that older immutable map version. The remaining UI migration work is final visual/accessibility review and removal of obsolete presentation-only paths. See the [UI integration plan](../../docs/migration/OPENOFFICE_UI_INTEGRATION.md).

## Current integration boundary

The browser API adapter uses the existing NestJS `/api/auth/*`, `/api/workspaces` and invitation-acceptance contracts. It validates public schemas, uses same-origin cookies, keeps CSRF in memory, and sends JSON mutations without automatic command retries. Company creation and invitation acceptance retain an in-memory idempotency key for an explicit retry of an uncertain result. Account changes discard prior client state.

Available account screens cover registration, email verification and resend, login, forgotten/reset password and logout. The company screen lists owner/member roles, creates a company and accepts a recipient-bound invitation code. Owner invitation management is removed from the active UI by owner request; its API and unmounted component remain available for future integration. Selecting a company opens the office shell directly, after authorized detail loading, and provides office entry through authenticated bootstrap, a one-use join ticket and Socket.IO. The supplied office-shell structure hosts the server-selected, versioned map (Vivo in the current environment) and supports movement, availability, seats and reconnect flows. Participant appearance comes from the office snapshot and is rendered against the currently approved base sprite; profile customization is not implemented. Issue #17 extends the supplied OpenOfficeForAll chat view with General and Social channels plus private one-to-one DMs selected from the space member directory. General preserves the original office-channel history. Scoped HTTP APIs and authorized private Socket.IO events keep conversations separate; the UI preserves drafts/retry IDs per conversation. History is limited to 100 messages with 90-day retention. Nearby chat and files remain unavailable. CP08.3b adds nearby-voice opt-in and a microphone control to the supplied office shell, backed by the session-bound API token and a lazy `livekit-client` adapter; microphone publication remains off until the user activates the microphone and the current group is media-ready. CP08.3c verifies the API policy-pull/install-ack flow with a separate guard process and an app-issued token against a mock signaling upstream. The real browser session still has no deployed guard/SFU path or proven audio. Fixed meetings, camera and screen sharing are reserved for CP09. Calendar/activity views remain explicit placeholders. Account security lists/revokes sessions, signs out all sessions, verifies the password, changes it. Expiry cleanup runs invisibly at the account root using the earlier idle/absolute deadline; no sign-in status card or Keep working button is rendered. The browser refreshes company details against the API and clears selection when you switch views, sign out or lose access.

Nearby-voice microphone permission is requested immediately from the user's microphone click, before coworker pairing or media-token authorization. The temporary permission-check stream is stopped as soon as the browser resolves it; LiveKit still obtains its own capture only after the server returns an authorized media grant. Waiting permission and connection stages are shown separately. To inspect timings locally, add `?debugVoice` to the app URL and check the browser console for `[proximity-audio]` events. Each event has a `performance.now()` timestamp (`atMs`); `permission-resolved` duration includes the user's browser-prompt decision time, while later stage durations begin at conversation activation. This lets you calculate click-to-pairing time separately from prompt-decision time. Diagnostics contain only stage names and monotonic timing values, no tokens or audio. Subtract the `mic-click-permission-requested.atMs` timestamp from `microphone-published.atMs` for total activation latency, and report the permission-decision interval separately. A browser may ask again for a nonpersistent grant; the capture stage also has delayed guidance and cancellation.

Secure cookie authentication requires same-origin HTTPS with `APP_ORIGIN` matching the browser origin and `/api` forwarded to the private API. The plain HTTP Vite URL is for UI development; it does not establish production cookie behavior. Local browser verification uses disposable HTTPS/Mongo fixtures and reads test codes privately from the encrypted outbox. Real SMTP, persistent queue and ingress/proxy acceptance remain separate CP04 work; see [delivery batches](../../docs/planning/CP04_BROWSER_AND_DELIVERY.md).

The old `/config`, slug-based APIs, localStorage identity, raw `/ws`, P2P signaling and React/SVG office code remain migration material. They are not connected product features. Preserve upstream licensing/provenance when those files are later retired.

## Checks and compatibility

`pnpm check` covers formatting, lint, TypeScript, browser API regressions, shared import/map tests and production builds. TypeScript `strict` and unused-code checks remain enabled. This imported client uses the upstream settings for `noUncheckedIndexedAccess` and `exactOptionalPropertyTypes` (both false); the stricter package/API defaults are unchanged. Re-enable these extra checks as modules are migrated. Browser/server import restrictions and Rules of Hooks apply to the imported files; the full React compiler lint preset applies to the migrated `src/` feature code.

The public files were restored from the same pinned upstream commit and checked against its Git blob hashes. Preserve `LICENSE.upstream` and the asset README notices. Local-only private reference packs are excluded from Git. The complete source/asset provenance is recorded in [UPSTREAM_IMPORT.json](../../docs/migration/UPSTREAM_IMPORT.json).

## Microphone permission verification

Run `pnpm test:web` and `pnpm exec playwright test tests/e2e/company-office-preview.spec.ts`. The browser regression holds permission pending while no coworker is available, checks delayed guidance, cancels and resolves the late stream, denies/retries permission, and verifies that consent probes stop before waiting for a coworker. It also preserves the prejoin microphone choice and verifies the authorized connection can be cancelled. Signaling and capture are mocked in this test; it does not validate real sound or native permission-panel timing.

For device acceptance, use Chrome, Firefox, and Safari with a fresh permission state and an already-granted state. Check cold/warm loads and a slow connection, cancel or ignore the browser prompt, then retry. Confirm the device indicator turns off while waiting for a coworker and after leaving. Use `?debugVoice` on the office URL to collect startup timings before agreeing a production latency target; browser/OS decision time is measured separately.
